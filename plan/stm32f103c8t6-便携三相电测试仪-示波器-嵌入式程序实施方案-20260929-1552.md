## 1. 硬件资源分配（先定死，避免后续返工）

**关键约束**：LQFP48 上 OLED 占 PB10/PB11，SWD 占 PA13/PA14，晶振占 PD0/PD1；ADC 需要 3 路模拟输入；按钮 4 个。

| 功能 | 引脚 | 外设 | 说明 |
|---|---|---|---|
| UA 输入 | PA0 | ADC1_IN0 | 模拟输入 |
| UB 输入 | PA1 | ADC1_IN1 | 模拟输入 |
| UC 输入 | PA2 | ADC1_IN2 | 模拟输入 |
| K1 `MODE` | PB0 | GPIO 输入上拉，低有效 | 见 §4 |
| K2 `CH/SEL` | PB1 | 同上 | |
| K3 `RANGE` | PB5 | 同上 | |
| K4 `OK/BACK` | PB6 | 同上 | |
| OLED SCL / SDA | PB10 / PB11 | I2C2 400kHz | SSD1306，`0x3C<<1` |
| 采样触发 | 无引脚 | TIM3 TRGO → ADC1 外部触发 | 只用 TRGO，不占通道 |
| 控制节拍 | 无引脚 | TIM4 更新中断 1kHz | 沿用基线 |
| 状态灯 | PC13 | GPIO 推挽，低有效 | |
| 调试串口（预留不启用） | PA9 / PA10 | USART1 | 为后续上位机预留 |

**为什么用 TIM3_TRGO 触发 ADC 而不是软件启动**：软件启动的采样间隔受主循环抖动影响（I2C 回合计入），会直接污染频率与相位测量；`ADC_EXTERNALTRIGCONV_T3_TRGO` 让采样周期由定时器硬件决定，抖动 <1 个 ADCCLK。

| DMA | 用途 | 固定映射依据 |
|---|---|---|
| DMA1_Channel1 | ADC1 扫描结果 | RM0008 表 78 固定 |
| DMA1_Channel4 | I2C2_TX（OLED） | RM0008 表 78 固定 |

**定时器分工**：TIM4 = 1ms 控制节拍；TIM3 = 采样触发（`PSC=0, ARR=5624` → **12800 Hz，无误差**）；TIM2 保持空闲。注意 PB0/PB1 与 TIM3_CH3/CH4 重叠，本方案不用 TIM3 通道，故不冲突（此点写进 README 的引脚冲突说明）。

## 2. 采集与测量引擎

### 2.1 采样与缓冲

- ADC1 三通道**扫描**模式，`ContinuousConvMode=DISABLE`（由 TIM3_TRGO 触发），采样时间 **55.5 cycles** → 单通道 (55.5+12.5)/12MHz ≈ **5.67µs**，一次完整扫描 17µs，占 12800Hz 周期的 21%。
- DMA1_Channel1 **循环模式 + 半传输/传输完成中断**，实现**双缓冲**：中断内只置 `frame_ready[half]` 标志（与基线 `App_Tick` 同样"中断只做交接"的纪律），测量在**主循环**执行。
- 每通道 **256 点/帧 = 恰好一个 50Hz 周期 = 20ms 一帧**；缓冲 2×3×256×uint16 = **3072 B**（通道数与帧长集中在 `app_config.h`，改一处即可）。
- **相位偏斜的诚实处理**：单 ADC 顺序扫描使 UA→UC 有 2×5.67µs = **11.3µs** 固定偏斜（50Hz 下 0.2°）。该偏斜是**已知常量**，在相位计算中作为校正项显式扣除并写进注释，而不是假装没有。双 ADC 同时采样（`ADC1+ADC2` 双规则同步）列为扩展项 §9.3。

### 2.2 测量算法（`measure.c`，纯整数定点，无浮点/无 printf）

| 量 | 方法 | 精度控制 |
|---|---|---|
| 有效值 RMS | 先求均值去直流 → 求偏差平方和 → 整数牛顿迭代开方 | Q16 中间量，64 位累加，避免溢出 |
| 频率 | 上升沿零交叉检测 + **线性插值**取亚样本过零点 → 多周期平均 | 不插值仅 1.4°@50Hz，插值后约 0.1° |
| 相位差 | UA 与 UB/UC 过零点时差 × 360/T | 线性插值，扣除 §2.1 偏斜 |
| 相序 | 检查 UB 滞后约 120°、UC 滞后约 240° → `ABC`/`ACB`/`缺相` | 容差窗口可配 |
| 峰值/最小值 | 窗口内极值 | 用于波形页纵轴自检 |
| 三相不平衡度 | 由三路 RMS 计算 | 预留，数值页底行 |

`measure.c` **不引用任何 STM32 头文件**，输入是 `const uint16_t *` 原始样本，因此可在宿主机用解析生成的理想正弦（含 120° 移相、失真、缺相、反序）做确定性单元测试。

## 3. 需求 1：模式切换逻辑

### 3.1 模式定义

```c
typedef enum { MODE_TP = 0, MODE_SCOPE, MODE_COUNT } AppMode;   /* 三相测试 / 单路示波器 */
typedef enum { TP_VIEW_SUMMARY = 0, TP_VIEW_WAVE } TpView;      /* 三相：数值页 / 波形页 */
typedef enum { SC_VIEW_WAVE = 0, SC_VIEW_METER } ScView;        /* 单路：波形页 / 参数页 */
```

### 3.2 切换条件

主切换（`MODE_TP ↔ MODE_SCOPE`）**唯一入口是 K1 长按**，并同时满足：

1. 按住时长 ≥ `BTN_LONGPRESS_MS`（700ms）；
2. **不在编辑态**——编辑态下 K1 长按语义为"取消编辑"，不切模式（上下文优先级，从根上避免调参时误切走）；
3. 长按期间屏上显示确认提示（`SWITCH?` + 进度条）；**中途松手即取消，无任何副作用**；
4. 只在**松手沿**提交，且不参与 REPEAT 连发。

子视图切换（模式内）为 K1 短按，可连发，与主切换分离。

### 3.3 状态保存与恢复

每个模式各持有**独立上下文**（双份，切换即换用另一份）：

```c
typedef struct {
  uint8_t  view;        /* 子视图 */
  uint8_t  sel_ch;      /* 焦点通道 0..2；三相可 ALL */
  uint8_t  range_idx;   /* 垂直量程档 */
  uint8_t  tbase_idx;   /* 时基档 */
  uint8_t  trig_mode;   /* AUTO / NORMAL / SINGLE */
  int16_t  trig_level;  /* 触发电平（百分比） */
  uint8_t  frozen;      /* 冻结 */
  uint8_t  hist[3][WAVE_COLS];  /* 该模式自己的波形历史，使恢复瞬时且无残留 */
} ModeContext;
static ModeContext s_ctx[MODE_COUNT];
```

切换序列（`mode.c`，事务式，失败不留半成品）：
1. 源模式上下文即时保存（无需拷贝，本来就是活对象）；
2. `s_mode = target`；
3. 恢复目标模式上下文到显示/触发配置（量程、时基、触发电平、触发模式、冻结位）；
4. 清理目标模式的部分瞬态（触发状态机、本帧标志）；
5. `UI_InvalidateAll()` 强制整屏重绘（避免差分刷新把上一模式的残影留下）；
6. 记录日志 + 屏上提示 `MODE 3PH` / `MODE SCOPE` 约 1.5s。

**采集引擎不重启**：两种模式共享同一 DMA 缓冲与测量结果，只切换下游消费者，因此切换耗时 <10ms 且不掉数据。

### 3.4 防误触（多层，非单点）

| 层 | 措施 |
|---|---|
| 时间 | 700ms 长按门槛，远高于机械抖动（20ms 消抖已在前置过滤） |
| 上下文 | 编辑态屏蔽模式切换；浏览态才允许 |
| 提交时机 | 松手沿提交，按住不放不会反复切换；不参与 REPEAT |
| 视觉 | 长按期间进度条 + `SWITCH?` 提示，达成前不改变任何状态 |
| 恢复 | 中途松手 = 完全取消（状态未动，故无需回滚） |

## 4. 需求 2：四键功能分配

采用"**一个键一个稳定语义、模式内一致**"的方案，避免同一按键在不同页里含义漂移：

| 键 | 短按 | 长按 | REPEAT（长按后） |
|---|---|---|---|
| **K1 `MODE`** | 切换子视图（三相：数值↔波形；单路：波形↔仪表） | **切换模式** 三相↔单路（编辑态下 = 取消编辑） | 不参与 |
| **K2 `CH/SEL`** | 选中下一个通道（三相 `UA→UB→UC→ALL`；单路 `CH1→CH2→CH3`） | 进入连发 | 连续步进通道 |
| **K3 `RANGE/ADJ`** | 循环切换"调整焦点"（垂直量程 → 时基 → 触发电平 → 触发模式） | 进入/退出**编辑态** | 不参与（避免误入） |
| **K4 `OK/BACK`** | 编辑态 = 焦点值 +1 档；非编辑态 = **冻结/解冻** | 编辑态 = 取消并回退；非编辑态 = 复位视图/返回默认页 | 编辑态连续加档 |

**为什么 K3/K4 这样分工**：F103 上按键是唯一输入，"选择目标"与"改变目标"必须分开，否则调量程时会连带改时基。K3 负责"选谁"，K2/K4 负责"加/减"，K4 兼作冻结与返回——这是 4 键仪表最常见且能自解释的映射。

**可达性与反馈**：
- 长按/连发复用基线 `button.c` 已验证的状态机（消抖 20ms / 长按 700ms / 连发 150ms），扩展为 4 路实例化，保持纯逻辑可测；
- 任何按键事件触发**立即刷新**一次（不受 UI 节拍限制），保证手感 ≤50ms；
- 状态栏显示当前模式徽标与编辑态标记，屏底一行常驻按键提示。

## 5. 需求 3：OLED 版面、刷新策略与刷新率权衡

### 5.1 版面（128×64，逐行固定）

**三相 · 数值页**
```
 3PH  50.00Hz                                            SEQ ABC
 ───────────────────────────────────────────────────────────────
      230.4V        UA          ∠ 0.0°      ← 焦点通道 24px 大字
 ───────────────────────────────────────────────────────────────
   UB  229.8V  ∠-120.0°     UC  231.1V  ∠+120.0°   ← 两相 12px
   UNBAL 1.2%          IMB         K1 MODE  K4 HOLD
```
| 区域 | y | 内容 |
|---|---|---|
| 状态行 | 0–11 | 左 `3PH`；中 频率；右 相序 `SEQ ABC`（或有故障时 `ERRxx`，沿用基线的位掩码故障徽标） |
| 分隔线 | 12 | |
| 焦点数值 | 14–37 | 24px 数值 + 12px 单位（等宽字模，跳数不抖动） |
| 分隔线 | 40 | |
| 另两相 | 41–52 | 各 `通道名 + 值 + 相角` |
| 底行 | 53–63 | 左 不平衡度；右 按键提示 |

**三相 · 波形页**：状态行显示时基（`5ms/div`）与三通道标记；y=13–52 为波形带，3 条轨迹共时间轴 + 分格虚线 + 过零点标记；y=53–63 底部显示每格电压、Vpp、冻结标记。

**单路示波器页**：同一个波形带放大给单通道；叠加**触发电平虚线**与触发点符号；状态行显示通道/时基/量程/触发方式；底部显示 `Vpp / Vrms / f`。仪表页显示单通道的全部标量与最值。

### 5.2 刷新策略

- **双缓冲 + 差分刷新**：KK_OLED 只发送脏页，应用每帧从空白重画（沿用基线已验证的契约）。
- **局部裁剪**：用 `OLED_SetClipWindow()` 把波形绘制限制在波形带，使脏页稳定在 1–2 页，而不是全屏。
- **异步发送**：`OLED_UpdateDMA()`；若 `OLED_IsBusy()` 为真则**丢弃本帧**（丢帧不排队），保证 UI 延迟有界、不积压。
- **采集与显示解耦**：测量按 DMA 帧（20ms）更新；显示按 UI 节拍抽帧；测量结果以"只读快照 + 序号"发布，UI 读取序号一致的快照，避免撕裂。
- **三档刷新节拍**：

| 档 | 周期 | 适用 |
|---|---|---|
| `UI_FAST_MS` | 33ms（30fps） | 波形页 |
| `UI_NORM_MS` | 100ms（10Hz） | 数值页/仪表页 |
| 事件立即刷新 | 按键事件当拍 | 按键反馈、模式切换提示（每事件最多 1 次，防抖） |

### 5.3 刷新率权衡（把账算清）

I2C 400kHz 下，全屏 1024B 数据 + 命令 ≈ 1030B × 9bit ≈ 9.3kbit → **约 23ms**；差分刷新只发波形带 2 页（约 256B）→ **约 6ms**。

- 因此波形页 30fps 时 I2C 占用约 **18%**，且因为是 DMA 异步，**不阻塞**主循环与测量；
- 数值页 10Hz 占用 <1%，把余量留给测量；
- 若改用基线的阻塞刷新，30fps 需要 700ms/s 的纯阻塞时间，会直接拖垮按键与测量——这就是本方案选 DMA 的量化理由。
- **实测量级受限于屏幕本身**：SSD1306 全屏传输下限 ~23ms，故波形页 30fps 是差分刷新的上限，想要更高只能减少刷新区域或提高 I2C 速率（CCL 上限 400kHz 已到顶）。

### 5.4 字模（硬约束，沿用基线的教训）

KK_OLED **运行时不含字体数据**，缺字行为是"不画像素并按空格推进、不报错"。因此新增任何文案都必须重新生成字模，且**缺字检测必须按像素墨迹判定，不能用 `OLED_GetGlyphAdvance`**（该接口缺字时回退空格 advance，会让你永远测不出问题——这是基线已经踩过并留下反向守卫的坑）。需生成：
- 12px 子集：`3PH SCOPE UA UB UC V A Hz deg SEQ ABC ACB FREEZE HOLD RANGE TBASE TRIG AUTO NORM SINGLE UNBAL IMB ERR MODE` + `0123456789.-+°%:∠` 等界面实际字符；
- 24px 数字子集：`0123456789.`（含负号，因相角可能为负）。

生成走仓库既有的 LEDFont API 流程（`kk-oled-font` skill）。

```bash
arm-none-eabi-size build/Release/<name>.elf
```
预期：FLASH <64KB、RAM <20KB。预估 RAM ≈ 6KB（DMA 3KB + 显示双缓冲 2KB + 波形历史/工作区 1KB），Flash ≈ 32–42KB。用 `memory-analysis` skill 出符号排名报告。

### 7.3 上板验证（需要硬件）

用 `flash-openocd` + `serial-monitor` skill：确认帧计数器持续增长（证明 TIM3→ADC→DMA 通路真的在跑，而不是"屏幕有数但全是初值"）；用示波器核对采样触发频率与相序判定；确认 OLED 地址/列偏斜与实际模组一致。

## 9. 扩展方向（按性价比排序）

1. **串口数据输出 / 上位机**：`USART1` 已在引脚表预留，只需在测量快照发布处加一个输出点，不动调用方（基线 `signal_log` 就是这么设计的）。
2. **电流与功率**：3 路电流 → 有功/无功/功率因数（通道数已是配置项，加电流=改配置+加标量）。
3. **双 ADC 同时采样**：`ADC1+ADC2` 规则同步，UA/UB 零偏斜、UC 偏斜降为 1 个采样周期；代价是双 DMA 与双模式 HAL 复杂度上升。
4. **谐波分析 FFT/THD**：256 点 radix-2（自写或用 CMSIS-DSP），RAM 与实时预算需实测后定。
5. **相量图/矢量显示**：把三相相量与不平衡度画成极坐标矢量图，对小屏信息密度最高。
6. **两/三点校准 + 参数存 Flash**：把 `CAL_GAIN/OFFSET` 写 Flash 末页，避免每次重烧。
7. **单次触发与冻结**：`SINGLE` 触发模式与冻结波形（上下文结构已留位）。
8. **告警**：欠压/缺相/不平衡超限的阈值报警。
9. **电池与低功耗**：加电池采样（基线 `battery.c` 可直接复用）；若要 STOP 唤醒，按键必须从轮询改 EXTI（基线 README 已论证这一点）。
